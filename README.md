# Комплект задания Codex: предобработка и извлечение признаков

Тема исследования: «Проектирование и разработка интеллектуальной системы распознавания сонливости водителя при помощи формирования нечёткой базы знаний второго порядка».
Дата подготовки: 2026-10-05. Это спецификация и проверяемая заготовка, а не готовый или проверенный на DROZY детектор.

## Как использовать
1. Распакуйте комплект в репозиторий проекта, например `specs/preprocessing/`.
2. Положите предоставленный ПНСТ и изображение архитектуры в `research/inputs/`. Исходные приложения в архив не включены. DROZY храните вне Git; путь укажите в конфигурации.
3. Откройте `CODEX_PROMPT.md`, скопируйте весь текст в Codex, укажите путь к комплекту и локальному DROZY. Если интегрируете существующий проект, укажите его корень. Codex должен сначала изучить существующие интерфейсы.
4. Первый этап может быть реализован по готовым точкам DROZY без загрузки модели зрения. Это измерительный baseline, а не оценка сонливости.
5. Направление взгляда и подтверждение зевоты реализуются отдельными backend; пока они не проверены, результат должен явно содержать `unknown` / `proxy`.
6. После реализации вручную разметьте выборку по протоколу, запустите оценку, затем подключайте модуль к интеллектуальному ядру.

## Файлы
- `CODEX_PROMPT.md`: полное задание агенту.
- `AGENTS.md`: ограничения для разработки в области этого комплекта; скопируйте правила в область будущего модуля.
- `docs/SPECIFICATION.md`: границы, алгоритмы, формулы, интерфейсы и работа с нечёткой моделью.
- `docs/CONTRACT_INVARIANTS.md`: проверки связей полей, дополняющие JSON Schema.
- `docs/DROZY_ADAPTER.md`: реальный формат источника, аудит и синхронизация.
- `docs/VALIDATION.md`: ручная разметка, метрики и критерии приёмки.
- `docs/STANDARD_TRACEABILITY.md`: связь с пунктами стандарта и ограничения.
- `docs/ARCHITECTURE.puml`: редактируемая PlantUML-схема модуля.
- `configs/defaults.json`: стартовые параметры; это гипотезы для валидации.
- `schemas/feature_window.schema.json`: машинный контракт результата.
- `examples/feature_window.json`: синтетический пример, не результат DROZY.
- `reference/time_metrics.py`, `tests/test_time_metrics.py`: эталон интегрирования по времени и оконных событий с тестами.
- `templates/manifest.csv`, `templates/events.csv`, `templates/gaze.csv`: форматы входного манифеста и ручной разметки.
- `docs/SOURCES.md`: источники и происхождение проектных решений.

## Быстрая проверка заготовки
Из корня комплекта: `python -m unittest discover -s tests -v`.
Для полной проверки JSON Schema нужен пакет `jsonschema`; после установки: `python -c "import json,jsonschema; jsonschema.validate(json.load(open('examples/feature_window.json')),json.load(open('schemas/feature_window.schema.json')))"`.
Реальный датасет здесь не запускался: пользовательские записи не приложены. До валидации нет оснований заявлять точность, готовность к эксплуатации или соответствие стандарту целиком.
