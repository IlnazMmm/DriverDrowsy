# Правила разработки модуля

- Используйте требования из docs и machine-readable контракт. Изменения семантики фиксируйте ADR и major-version схемы.
- Не реализуйте сонливость, прогнозирование и нечёткое ядро в этом модуле.
- Не заявляйте полное соответствие ПНСТ на основании выполнения шести признаков.
- Не выдумывайте наличие файлов, модельных весов, разметки, measured accuracy или характеристик компьютера.
- Не считайте видео-DROZY или KSS покадровой разметкой моргания, взгляда или зевоты.
- Источники данных только read-only. В Git нет видео, лиц, PSG, секретов и скачанных весов.
- При разрыве timestamp не экстраполируйте состояние без лимита, не объединяйте события через разрыв.
- Никакой интерполяции будущими точками в online; статусы interpolated/repeated должны сохраняться.
- Любой unsupported признак -> null/unknown + причина, не «нормальное состояние».
- Пороговые значения defaults.json — гипотезы, не универсальные нормы.
- Сначала изучите существующий репозиторий. Сохраните интерфейсы, если нет обоснованной причины миграции.
- Доступность оборудования и веса проверять до обещания live backend. Рабочий DROZY baseline обязателен при доступных данных.
